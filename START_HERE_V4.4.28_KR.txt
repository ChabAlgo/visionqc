VisionQC v4.4.28 + Local Agent v0.2.6 시작 안내

1. Web 배포
   - GitHubPages_v4.4.28 폴더 안의 내용을 GitHub Pages 저장소 루트에 덮어씁니다.
   - index.html이 v4.4.28 자산을 가리키는지 확인합니다.

2. Agent 교체
   - 기존 Agent를 `Agent 종료` 버튼 또는 STOP_AGENT.cmd로 종료합니다.
   - LocalAgent_v0.2.6 폴더에서 BUILD_RELEASE_x64.cmd를 실행합니다.
   - 빌드 성공 후 REGISTER_PROTOCOL.cmd를 한 번 실행하고 RUN_AGENT.cmd를 실행합니다.
   - Web의 Local Engine 카드에서 Agent 0.2.6을 확인합니다.

3. 권장 작업 순서
   - Position별 Workspace와 이미지 폴더, Output을 선택합니다.
   - Workspace Runtime Structure 제목 오른쪽의 Runtime File Load를 누릅니다.
   - 최초 Workspace 로드는 VPDL 역직렬화 때문에 파일당 수십 초 걸릴 수 있습니다.
   - READY가 된 뒤 Simulation Start를 누르면 같은 Workspace를 다시 로드하지 않고 시작합니다.
   - 정상 완료/사용자 중지 후 같은 설정으로 다시 시작해도 사전 로드 Runtime을 재사용합니다.

4. Progress Update
   - 예: 3으로 설정하면 상세 분석 Batch와 진행률을 3장 단위로 Web에 전달합니다.
   - Progress Log에는 같은 경계의 INFO 중복 없이 PROGRESS 한 줄만 남습니다.

5. 알림
   - 좌측 🔔 아이콘의 숫자는 읽지 않은 오류·경고 수입니다.
   - 아이콘을 열면 숫자는 사라지고 기록은 남습니다.

현장 필수 확인
   - Windows 파일/폴더 선택 창이 화면 앞에 표시되는지
   - Runtime File Load 완료 후 Simulation Start에서 `워크스페이스 로드 중` 장시간 대기가 다시 발생하지 않는지
   - Cognex VPDL 4.0 실제 License/GPU 및 Workspace 3개 조합

주의
   - 이 배포 환경에서는 Windows Cognex VPDL Runtime을 실행할 수 없어 실제 VPDL 처리 검증은 현장 PC에서 수행해야 합니다.
