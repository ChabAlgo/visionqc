VisionQC v4.3.7 실제 브라우저 상호작용 테스트 결과

테스트 환경
- Chromium Headless
- 화면 크기 1920 x 1080
- 로컬 정적 서버 http://127.0.0.1:3021
- 실제 마우스 press/release 이벤트를 Chrome DevTools Protocol로 전달

통과 항목
1. 메뉴 버튼 mousePressed 시 메뉴가 열리지 않음
2. 같은 클릭의 mouseReleased 후 메뉴가 1회만 열리고 열린 상태 유지
3. 메뉴의 설정 항목 클릭 후 body page=settings 전환 확인
4. 설정 화면 제목 '분석 Input 설정' 렌더링 확인
5. 설정 화면 '전체 초기화' 실제 마우스 클릭 후 confirm 호출 1회 확인
6. 메인 빈 화면의 'Input 설정 열기' 실제 마우스 클릭 후 settings 전환 확인
7. 비분류 화면에서 document.elementFromPoint가 확장 화면의 실제 요소를 반환하는지 확인
8. 상단 2줄 배치 좌표 확인
   - 1행: Input Cell ID / Load Folder / Load Files
   - 2행: Label Reset / ZIP / Organize Folder / Export Folder
9. JS 문법 검사(node --check) 통과
10. 정적 서버 파일 응답 및 ZIP 무결성 검사 통과

핵심 수정 원인
- 이전 버전은 메뉴를 pointerdown과 click 양쪽에서 토글할 가능성이 있어 누를 때 열리고 뗄 때 닫힐 수 있었음
- 전역 pointerdown 캡처에서 preventDefault/stopImmediatePropagation을 사용해 select와 일반 버튼의 기본 클릭 동작을 차단할 수 있었음
- v4.3.7에서는 메뉴를 단일 click으로만 처리하고 전역 pointerdown 캡처를 제거함
- 메인/분석/설정의 data-vq-action 버튼에 직접 onclick을 연결함
- 비분류 화면에서는 기존 분류 main을 display:none 처리함
